## ⚠️ Breaking Changes

### Standardsprache ist jetzt Englisch

Aufrufe ohne `lang` liefern englische Inhalte. Bisher war Deutsch der Standard.

```bash
# vorher: deutsch
curl "https://kern.lukasbaumert.de/lookup/7"

# jetzt: englisch. Für das alte Verhalten:
curl "https://kern.lukasbaumert.de/lookup/7?lang=de"
```

### `GET /` liefert nicht mehr die Hilfe

`/` ist jetzt ein schlanker Service-Deskriptor für Health-Checks. Die vollständige Endpunkt-Übersicht liegt auf **`GET /help`**.

```json
{"name":"KERN API","version":"2.0.0","languages":["de","en","fr"],
 "default_language":"en","documentation":"/help"}
```

## Neu

### Drei Sprachen

| Inhalt | en | de | fr |
|--------|:--:|:--:|:--:|
| Zahlenbedeutungen | ✅ | ✅ | ✅ |
| SPEKTRA- und RTAP-Prompts | ✅ | ✅ | ❌ |

Steuerung über `lang` in der API und `--lang` im CLI. Regions-Subtags werden toleriert (`en-US` → `en`).

### Keine stillen Fallbacks

Eine Sprache, die es für die angefragte Ressource nicht gibt, wird abgelehnt statt durch eine andere ersetzt:

```json
{"code":"language_not_available","error":"prompts are not available in 'fr'. available: de, en"}
```

Wer Französisch anfragt, bekommt kein Englisch untergeschoben. Jede Antwort nennt im `lang`-Feld die verwendete Sprache.

### Stabile Fehlercodes

Alle Fehler von **API und CLI** tragen jetzt einen maschinenlesbaren `code` neben dem menschenlesbaren Text:

```json
{"code":"invalid_range","error":"invalid range specification"}
```

Gegen `code` programmieren, nicht gegen `error` — der Text ist Prosa und darf sich ändern. Fehlermeldungen sind immer Englisch; `lang` steuert Inhalte, nicht das Protokoll.

## Behobene Fehler

- Gepiptes `kern -l <wort>` meldete für jeden Eintrag `"number": 0`.
- CLI und Server nannten denselben Sachverhalt unterschiedlich (`invalid_arguments` statt `insufficient_inputs`).
- `parse_range` gab deutsche Fehlertexte durch eine ansonsten englische API zurück.
