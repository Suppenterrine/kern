CLI und Server rechnen jetzt über denselben Code. Bisher hatten sie zwei getrennte Implementierungen — mit unterschiedlichen Ergebnissen.

---

## ⚠️ Breaking Changes

Beide betreffen **nur `/reduce`** und rühren daher, dass der Endpunkt eine
eigene, abweichende Kopie der Reduktionsroutine benutzte.

### `chain` hat ein anderes Format (nur mit `cipher=…&debug=true`)

```bash
# vorher
GET /reduce?input=Test&cipher=or&debug=true
→ "chain": ["Test", "64", "10"]

# jetzt
→ "chain": ["20+5+19+20 = 64", "6+4 = 10", "1+0 = 1", "→ 1"]
```

Das alte Format war zusätzlich **unvollständig** — der Endwert fehlte. Und es
galt nur bei gesetztem `cipher`: ohne den Parameter lieferte derselbe Endpunkt
schon immer das neue Format. Zwei Formate in einem Endpunkt, je nach
Parameterwahl.

### `total` summiert jetzt über alle Chiffren

```bash
GET /reduce?input=Test&cipher=all&total=true
# vorher: nur der Wert der ersten Chiffre
# jetzt:  Summe aller 11 Chiffren → 4
```

Das entspricht dem, was `kern --cipher all Test -t` seit jeher liefert.

## Was dahintersteckt

`/reduce` war der letzte Pfad, der die Flow-Engine **nicht** benutzte. Er
rechnete direkt, mit einer privaten Kopie von `reduce_number_steps_with_cipher`,
die sich von der Bibliotheksfassung unterschied. Zwei Codepfade für dieselbe
Rechnung sind die eigentliche Ursache solcher Abweichungen — deshalb ist die
Kopie jetzt weg und der Endpunkt läuft über dieselbe Engine wie das CLI.

## Aufgeräumt

Vier Stellen der Flow-Engine sahen nach Funktionalität aus, hatten aber keine.
Sie stammten aus einem Entwurf für „Flags pro Pipeline-Position", der nie
gebaut wurde. Entfernt, ohne Verhaltensänderung:

| Entfernt | War |
|----------|-----|
| `Operation::Custom(String)` | wurde nirgends erzeugt, der Zweig war leer |
| `_step` in `select_ciphers` | Parameter wurde nie gelesen |
| `cipher_index` in `Step::new` | von `run()` überschrieben, bevor ihn jemand las |
| verworfenes `ResultSet` im SPEKTRA-Pfad | Rückgabewert weggeworfen zugunsten von `ctx.memory` |

Für Nutzer der Rust-Bibliothek: `Step::new` nimmt jetzt
`(pipe_index, operation)`, und `Operation::Custom` gibt es nicht mehr.

## Noch offen

Der Reihenfolge-Vertrag der Engine bleibt ungeschrieben: `AggregateTotal` und
`Lookup` müssen nach den Reduce-Schritten eingefügt werden, sonst liefern sie
stillschweigend 0. Dokumentiert in `docs/reference/flow-engine.md`, aber noch
nicht erzwungen.
